# «Моё решение»: редактирование Python и визуализация собственного запуска

Статус: предложение для согласования. Продуктовый код не изменён.

## Зачем

Пользователь хочет не только читать готовое решение, но и вставлять свой Python-код, менять алгоритм и наблюдать его выполнение на существующих примерах задачи. Эталон должен оставаться доступным для сравнения. В первой версии это одна текущая версия собственного решения на задачу, без аккаунта и истории версий.

## Сценарий

1. На странице задачи рядом доступны «Эталон» и «Моё решение».
2. «Эталон» сохраняет существующий просмотр и воспроизведение подготовленных примеров.
3. При первом открытии «Моё решение» показывается заготовка с именем функции и параметрами выбранной задачи. Тело не содержит готовый ответ. Сохранённый черновик имеет приоритет над заготовкой.
4. Пользователь может вставить код, изменить заготовку или явно выбрать «Скопировать эталон». Последнее заменяет черновик только после подтверждения, если в нём есть свои изменения.
5. «Запустить пример» выполняет код на выбранном из четырёх примеров. Результат сравнивается с ожидаемым; сохраняется трасса для плеера.
6. «Проверить все примеры» выполняет четыре примера, показывает результат каждого и позволяет выбрать запуск для просмотра. У каждого примера отдельные входные данные и состояние Python.
7. Пользователь проигрывает или листает собственный запуск: видит активную строку своего кода, изменения переменных, структур и результат. Неверный ответ тоже можно разбирать по шагам.
8. Правка кода помечает прошлые результаты устаревшими и останавливает проигрывание. Редактируемый текст не подсвечивается строкой старой трассы. До нового запуска старый результат не выдаётся за результат изменённого кода.
9. Черновик сохраняется отдельно для каждой задачи в этом браузере. Перезагрузка, переходы по задачам и переключение тем не сбрасывают его. При отказе хранилища редактор работает в памяти и сообщает, что сохранение недоступно.
10. Успешный запуск примеров не отмечает задачу автоматически и не начисляет XP. Существующая ручная отметка и правила первого закрытия сохраняются.

## Редактор и шаблон

Редактируется Python-код решения, а не HTML или JavaScript. Существующая сигнатура функции — контракт подключения к примерам: имя функции и именованные входные параметры должны поддерживаться. Внутренние переменные, вспомогательные функции и подход к решению можно менять.

Редактор предоставляет нормальный многострочный ввод, отступы, подсветку Python и номера строк. При ошибке показываются тип, сообщение и строка пользовательского кода, когда Python её сообщает. Служебный код запуска не смешивается с редактируемым решением.

Заготовка, скопированный эталон, сохранённый черновик и снимок выполненного кода — разные сущности. Просмотр эталона никогда не перезаписывает черновик. Копирование эталона и сброс черновика — явные действия.

Адаптеры текущих задач для списков, деревьев, графов и trie остаются доступными в среде исполнения как `curriculum.structures`. Технически необходимые определения доступны через существующий раздел структур данных. Это обеспечивает выполнение текущих эталонов с их импортами.

## Исполнение

Рекомендация разработчика: Python через Pyodide/WebAssembly в отдельном module Web Worker. Это сохраняет размещение на GitHub Pages без нового backend и позволяет прерывать зависший запуск завершением worker. Worker отделяет вычисления от интерфейса; это не обещание отдельной защищённой серверной песочницы.

Среда загружается при первом запросе запуска, а не при обычном чтении эталона. На загрузке видны статус, возможность отмены и понятная ошибка с повторной попыткой. Для первого запуска нужен доступ к файлам среды; офлайн-запуск заранее не гарантируется.

Версия Pyodide фиксируется при реализации по проверенной официальной документации; плавающий URL `latest` не используется. Стандартная библиотека и адаптеры задач включены в объём. Установка произвольных сторонних пакетов и обращения к внешним сервисам не относятся к первой версии.

Каждый пример получает свежие globals и копию аргументов; изменённые массивы и узлы не переходят в следующий пример. Состояния узлов, стек вызовов и строки соответствуют реальному исполнению пользовательского кода.

Есть кнопка «Остановить», тайм-аут выполнения и ограничение числа/объёма снимков. Стартовые ориентиры разработчика: до 1800 кадров на пример и 10 секунд вычислений на пример; инициализация среды имеет отдельный лимит ожидания. Окончательные ограничения уточняются проверкой на всех эталонах. Превышение лимита явно обозначается; обрезанная трасса не считается успешным завершением.

Отмена, переход на другую задачу и новый запуск делают устаревшие ответы worker недействительными. После остановки можно запустить код снова. Загрузка среды и выполнение имеют разные состояния; интерфейс остаётся отзывчивым.

## Честная визуализация собственного кода

Текущие специализированные сцены читают конкретные имена переменных: например, `left`, `right`, `mid`, `dp`, `heap`. Пользователь не обязан повторять внутренние имена эталона.

Поэтому для собственного кода обязателен универсальный просмотр состояния: реальные локальные переменные, массивы/строки, словари/множества, матрицы, узлы поддерживаемых структур и стек вызовов. Он показывает значения и изменения между кадрами, включая новые имена переменных.

Специализированная сцена задачи используется только при наличии совместимых данных. Если совместимости нет, доступен универсальный просмотр с понятной подписью. Нельзя подставлять массивы, указатели или сообщения из записанного эталона и выдавать их за работу пользовательского алгоритма.

Имена индексных переменных не превращаются в указатели на случайный массив: специализированный режим использует существующий контракт сцены, универсальный показывает фактические значения без догадок о смысле имён. Автоматическое распознавание произвольного алгоритма и его оптимальности не обещается.

Обычные Python-данные сериализуются ограниченно; для неподдерживаемого типа показывается ограниченное текстовое представление. Если представление данных сокращено из-за размера, это видно пользователю. Точность сравнения ответа не должна зависеть от сокращённого снимка визуализации.

## Ошибки, результаты и прогресс

- Синтаксическая ошибка: исправляемый редактор и сообщение со строкой; нет выдуманного результата.
- Исключение при исполнении: сообщение и доступная предшествующая трасса без отметки об успешном завершении.
- Неверный ответ: отдельно фактическое и ожидаемое значения; трасса доступна для разбора.
- Совпадение ответа: «Совпало на примере», без утверждения полной корректности алгоритма по четырём тестам.
- Бесконечный цикл/слишком большой запуск: остановка по лимиту и доступное повторное выполнение.
- Вывод `print` отображается отдельно с ограничением объёма.
- Учебный прогресс, XP, календарь и дата первого закрытия не меняются от редактирования или запуска кода.

## Проверка перед сдачей

- Все 101 текущий эталон запускаются новым движком на всех 404 примерах и дают прежние ответы.
- Ручной алгоритм бинарного поиска с другими именами переменных показывает свою трассу; неверный вариант показывает собственную ошибку.
- Рекурсия, списки/деревья/графы с адаптерами, стандартные импорты и вспомогательные функции работают.
- Проверены синтаксическая ошибка, исключение, пропущенная функция, несовместимая сигнатура, неверный ответ, бесконечный цикл, остановка и повторный запуск.
- Черновики изолированы по задачам; эталон и результаты других задач не перезаписываются. При правке виден устаревший статус старого прогона.
- Ошибка загрузки Pyodide и недоступное хранилище не ломают существующие страницы и эталонный плеер.
- Проверены обе темы, мобильный ввод и существующий полный набор проверок сайта.

## Вне этого изменения

Свой backend, учётные записи, синхронизация между устройствами, полноценная IDE, установка произвольных пакетов, редактор собственных тест-кейсов и автоматическое признание задачи решённой. Пользователь пока запросил работу с существующими примерами.

## Решения, предлагаемые разработчиком

- Начинать «Моё решение» с заготовки; перенос эталона — по отдельной кнопке.
- Сохранять один черновик на задачу локально.
- Работать в браузере без backend, чтобы сохранить GitHub Pages.
- Универсальный просмотр гарантировать; специализированные сцены использовать по совместимости данных.
- Автоматически не менять существующий учебный прогресс.

Эти решения предлагаются для согласования; отдельный план реализации следует после утверждения описания.

## Проверка описания

Независимая проверка на достаточность для составления плана завершена: существенных неотвеченных вопросов не обнаружено. Реализация не начиналась.

Техническая опора: [официальная документация Pyodide — исполнение в Web Worker](https://pyodide.org/en/stable/usage/webworker.html). Она подтверждает возможность выполнять Python вне потока интерфейса; конкретная закреплённая версия и совместимость адаптеров проверяются при реализации.
