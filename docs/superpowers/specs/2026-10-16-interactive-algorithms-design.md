# Интерактивный Coding Interview Patterns

Дата: 16 октября 2026 года. Статус: согласовано пользователем; реализация и проверки выполняются.

## Результат

Публичный учебный сайт в репозитории [GLec1er/algorithms](https://github.com/GLec1er/algorithms), опубликованный на GitHub Pages. Он сопровождает книгу **Coding Interview Patterns** Alex Xu и Shaun Gunawardane: все 19 глав и 101 задача получают объяснения и пошаговые визуализации.

Главная цель — видеть, как меняется состояние алгоритма: какие элементы сравниваются, куда перемещаются указатели, почему меняются границы, как добавляются и удаляются элементы, какие решения сохраняются или откатываются. Сайт должен помогать распознавать паттерны в новых задачах.

## Требования пользователя

- GitHub Pages в указанном репозитории.
- Покрытие каждой главы и каждой задачи книги.
- Наглядная анимация работы алгоритмов, включая бинарный поиск, стеки и интервалы.
- Объяснение, для каких задач применяется соответствующий алгоритм.
- Код решений на Python — подтверждено пользователем.

## Предлагаемые решения

Эти решения выбраны исполнителем и входят в предлагаемое описание:

- Интерфейс, объяснения и подписи — по-русски; исходные английские названия задач сохраняются для сверки с книгой.
- Каждая глава содержит вводный разбор паттерна, типовые признаки подходящих задач, ограничения и список входящих задач.
- У каждой задачи собственная работающая трассировка её алгоритма. Общий движок и визуальные элементы можно переиспользовать; одинаковая анимация паттерна вместо решений разных задач не считается покрытием.
- Рядом с анимацией находятся Python-код, подсветка текущей строки и значения переменных.
- У каждой задачи не менее двух заранее подготовленных примеров: основной и показательный граничный. Примеры выбраны так, чтобы анимацию можно было проследить вручную.
- Воспроизведение, пауза, шаг назад, шаг вперёд, возврат в начало, выбор скорости и переход по шкале шагов.
- Поиск по русским и английским названиям, фильтры по главе и сложности, ссылки на отдельные задачи.
- Локальное сохранение последней открытой задачи и отметок «разобрано»; сайт работает без регистрации.
- Спокойный учебный интерфейс с крупной рабочей областью и постоянной легендой цветов. Цвет дополняется подписями, рамками и символами.
- На узком экране блоки располагаются последовательно, управление воспроизведением остаётся доступным. Крупные схемы допускают прокрутку внутри рабочей области.

## Структура занятия

1. Краткое условие своими словами и пример входа/ожидаемого результата.
2. «Как распознать паттерн»: признаки, при которых подход полезен, и необходимые предпосылки.
3. Визуализация с управлением шагами и выбором примера.
4. Текст текущего действия: что изменилось и почему следующий шаг корректен.
5. Python-код с синхронной подсветкой; значения указателей, коллекций и счётчиков.
6. Итоговый результат, временная и пространственная сложность, ключевые крайние случаи и распространённые ошибки.
7. Ссылки на исходную задачу и связанные задачи внутри сайта.

Для главы вводная анимация объясняет общий приём на репрезентативной задаче. Эта задача также остаётся доступной как полноценное занятие в каталоге.

## Как должны выглядеть изменения состояния

| Семейство | Что видит ученик |
| --- | --- |
| Массивы, два указателя, окна | Индексы, движение указателей, выделенный диапазон, сравнения, перестановки, содержимое окна и текущий ответ. |
| Hash maps и sets | Связь текущего элемента с ключом, добавление/поиск/удаление, обновление частот и обнаружение повторов. |
| Связные списки | Стабильные идентификаторы узлов, направления ссылок, изменение связей, положение указателей; для LRU также порядок использования и таблица поиска. |
| Быстрый и медленный указатели | Независимые перемещения, встреча в цикле или достижение конца; для Happy Number — последовательность чисел. |
| Бинарный поиск | Текущий диапазон кандидатов, midpoint, проверяемое условие и явно показанная причина исключения части диапазона. Поиск по ответу показывает также проверку допустимости. |
| Стеки и очереди | Операции push/pop с выделением вершины, направление переноса, соответствие открывающих/закрывающих скобок; для монотонной очереди — удаление устаревших и неподходящих элементов. |
| Кучи | Дерево и представление массивом, приоритеты, вставка/извлечение и восстановление порядка; для медианы — две кучи. |
| Интервалы | Отрезки на общей числовой оси, сортировка, сравнение границ, объединение и результат; для sweep line — события и число активных отрезков. |
| Префиксные суммы | Строительство префиксов, связь диапазона с двумя границами, накопленные значения и поиск ранее встречавшейся суммы. |
| Деревья и tries | Посещаемый узел, выбранные рёбра, очередь или стек обхода, возвраты рекурсии, значения подзадач; терминальные узлы слов отмечены отдельно. |
| Графы | Посещённые вершины/клетки, frontier, расстояния, parent, indegree или компоненты — в зависимости от конкретного алгоритма. |
| Backtracking | Частичное решение, выбор, проверка ограничения, ветвление, откат и найденные решения. |
| Динамическое программирование | Смысл состояния, таблица/массив, зависимости текущей ячейки, применяемый переход и итоговый ответ. |
| Жадные алгоритмы | Текущий выбор, доступные варианты и сохраняемый инвариант; основание корректности объясняется отдельно. |
| Сортировки и поиск порядковой статистики | Сравнения, перемещения элементов, разделение на части, слияние либо partition и изменение рабочего диапазона. |
| Битовые операции | Биты с номерами разрядов, маски, XOR/AND/сдвиги и изменение результата. |
| Математика и геометрия | Координатная сетка, направления/границы обхода, преобразования чисел или исключение элементов по кругу — согласно задаче. |

Для геометрии, графов и деревьев расположение объектов помогает чтению; алгоритм определяется данными и связями. Перетаскивание узлов пользователем и редактор произвольных структур в начальный объём не входят.

## Два конкретных сценария

**Бинарный поиск: Find the Insertion Index.** На массиве `[1, 3, 5, 6]` с целью `2` показываются `left`, `right`, `mid` и возможная позиция вставки. На каждом сравнении поясняется, почему часть позиций исключается. Финал выделяет индекс `1`; пример с целью `7` показывает допустимую позицию после последнего элемента. Выбор закрытого или полуоткрытого диапазона совпадает с показанным Python-кодом и не меняется внутри трассировки.

**Интервалы: Merge Overlapping Intervals.** Для `[[1, 3], [2, 6], [8, 10]]` сначала виден порядок по началу, затем сравнение `[1, 3]` и `[2, 6]`, изменение правой границы до `6` и перенос результата в отдельную строку. Для закрытых интервалов касание границ считается пересечением; для иных соглашений в конкретной задаче это явно указано.

## Техническое решение

Предлагаемый исполнителем стек: статическое приложение на **TypeScript, React и Vite**, SVG/HTML для схем и CSS-переходы для движения. Сервер и база данных для этого объёма не нужны. Развёртывание — **GitHub Pages**, отдельный хостинг Sites не создаётся.

- Каталог и учебные тексты разделены с генераторами шагов и визуальным представлением.
- Для каждого примера при сборке выполняется реальный Python и записывается последовательность воспроизводимых состояний: данные сцены, активная строка кода, переменные, пояснение и признак завершения.
- Отображение состояния не запускает сам алгоритм повторно. Пауза, шаг назад и переход по шкале используют ту же последовательность.
- Узлы и элементы сохраняют идентичность при перестановке, чтобы перемещение оставалось понятным.
- Python-код одновременно служит решением и источником фактических состояний. TypeScript в браузере воспроизводит их; дублирование алгоритмов устранено при составлении плана. Произвольный запуск Python и редактор кода в этот объём не входят.
- Генерация обрывается при заданном пределе состояний; примеры для экспоненциальных алгоритмов малы. Псевдослучайные примеры используют фиксированное начальное состояние и воспроизводятся при сбросе.
- Маршруты задач через hash и корректный base `/algorithms/` обеспечивают открытие прямых ссылок на GitHub Pages без серверных rewrite.
- Главы загружаются по мере открытия; первый экран не требует загрузки трассировок всех задач.
- `prefers-reduced-motion` отключает плавные перемещения, сохраняя пошаговый смысл. Управление доступно с клавиатуры; автоматическое воспроизведение не включается без действия пользователя.

## Материалы

Объяснения, схемы, примеры и реализации создаются самостоятельно. Названия и соответствие задачам сверяются с официальными источниками; со страницы занятия доступна ссылка на первоисточник. Полный текст книги и её иллюстрации не публикуются.

Покрываются все 101 задача официального онлайн-каталога, включая добавленные авторами задачи из бонусных материалов. Дополнительные задачи вне этого перечня не входят в текущий объём. Если у пользователя иное издание с отличающимся оглавлением, каталог потребуется сверить.

## Проверки перед завершением

- Каталог: ровно 19 глав, 101 уникальная задача; у каждой есть текст, Python-код, генератор шагов, примеры и ожидаемые результаты.
- Для каждого примера итог трассировки сверяется с ожидаемым ответом. Для неоднозначного порядка результатов сравнивается нормализованное представление.
- Для ключевых генераторов проверяются независимые инварианты и граничные случаи: границы поиска, порядок стека/кучи, достижимость в графе, объединение интервалов и переходы DP.
- Python-решения выполняются на тех же примерах и сопоставляются с результатами визуализации; подсветка проверяется на представительных трассировках каждой семьи сцен.
- Интерфейс: пауза/возобновление, шаг назад, сброс, смена примера и задачи, скорость, шкала, навигация клавиатурой, поиск и локальные отметки.
- Визуальная проверка всех семейств сцен на широком и узком экране; для каждой из 101 задачи — открытие занятия и прохождение примера до конца без ошибок.
- Production-сборка проверяется под `/algorithms/`, включая прямое открытие ссылок и загрузку ресурсов.
- Публикация считается подтверждённой после успешного workflow GitHub Pages и проверки открывающегося публичного адреса.

## Публикация и текущее состояние

На момент осмотра удалённый репозиторий содержит только `.gitignore`, `LICENSE` и короткий `README.md`, ветка по умолчанию — `main`. Локальная копия размещена в `work/algorithms`; пользовательские изменения отсутствовали. Метаданные GitHub сообщают `has_pages: true`, но источник публикации и доступность самого сайта ещё не подтверждены.

Предлагается GitHub Actions workflow: проверки и сборка на pull request; проверенная сборка и развёртывание при обновлении `main`; ручной запуск при необходимости. Права workflow ограничиваются чтением содержимого, публикацией Pages и OIDC для deployment. Точные поддерживаемые версии actions сверяются при реализации.

Ожидаемый стандартный адрес — `https://glec1er.github.io/algorithms/`; это целевой адрес, а не утверждение о готовой публикации.

Первичная проверка `gh` внутри сетевой песочницы не прошла. Повторная проверка вне неё подтвердила действующий вход GLec1er и чтение Pages-настроек. Источник Pages — legacy/main, при публикации он переводится на GitHub Actions.
